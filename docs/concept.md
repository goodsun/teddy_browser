# Teddy Browser — コンセプト 🧸

## ビジョン

**AIが「目」と「手」を持ち、人間と同じ画面を見ながら一緒に作業する。**

テディはこれまでAPIとテキストだけでWebと対話していた。
teddy_browserによって、人間と同じようにブラウザで画面を見て、操作できるようになる。

## 核心：ペアワーク

マスターとテディが **同じページを同時に見ながら** Telegramで会話して作業する。

```
マスター（ブラウザ）  ←→  Telegram  ←→  テディ（teddy_browser）
     ↕                                        ↕
   同じGoogleドキュメント / Webページ / スプレッドシート
```

### ユースケース

#### 📝 共同編集
- Google Docsを一緒に編集 — マスターが本文、テディが校正・補足
- スプレッドシート整理 — マスターが構造決めて、テディがデータ入力
- note.com記事の共同執筆 — マスターが構想語る → テディがリアルタイムで下書き

#### 👀 レビュー＆フィードバック
- 「このサイトどう思う？」→ テディがスクショで実際に見て具体的にコメント
- デザインレビュー、コードレビュー、記事レビュー
- 競合サイト分析 — 一緒に見ながら議論

#### 🔧 ブラウザ操作の代行
- テディがログインしてフォーム入力、設定変更
- API化されてないサービスの操作（管理画面等）
- Cookie/セッション問題のデバッグ（実際の画面を見ながら）

#### 🎯 リサーチ
- マスターが「これ調べて」→ テディがブラウザで巡回してスクショ＋要約をTelegramに返す
- 複数サイトを横断して情報収集

## GPU脳 × AIアシスタント

マスターのPRI:130（視覚推理）は、画面を見れば一瞬で全体像を掴む。
でも言語化（VCI:108）が追いつかない。

テディが同じ画面を見ていれば：
- マスター：「ここ、こうしたい」（短い指示）
- テディ：画面を見て意図を理解 → 実行＆言語化

**短い指示で通じる** ——これがペアワークの本質。

## 技術的な実現

### 1. 常駐モード
- Playwright起動は重い → 立ち上げっぱなしで即コマンド投入
- WebSocketまたはstdinパイプで常時接続

### 2. Telegram連携
- 「ここ見て」→ テディがURLを開いてスクショをTelegramに送信
- マスターからの指示に応じてブラウザ操作 → 結果をスクショで報告

### 3. セッション管理
- プロファイルでCookie/localStorage維持
- Google、note.com、X等のログイン状態を保持
- 複数プロファイル切り替え

### 4. セキュリティ
- 認証情報はプロファイルに暗号化保存
- マスターの個人情報はブラウザ内に留める
- 操作ログを記録（監査可能）

## 既存ツールとの関係

| ツール | 役割 | teddy_browserとの違い |
|---|---|---|
| curl/requests | API直叩き | UI操作不可、認証が複雑 |
| OpenClaw browser | 汎用ブラウザ制御 | テディ専用の最適化なし |
| Playwright (x_post.py等) | 単機能スクリプト | 汎用的な対話操作不可 |
| **teddy_browser** | **AI専用の目と手** | **スクショ確認＋対話操作＋セッション維持** |

## MVP（達成済み ✅）

テディがteddy_browserでページを操作し、スクショをTelegramに送る。
マスターはTelegramで画面を見ながら指示を出す。それだけ。シンプル。

```
マスター: 「〇〇開いて」
テディ: teddy_browser → 操作 → スクショ → Telegram送信
マスター: 「ここ変えて」
テディ: 操作 → スクショ → 送信
```
